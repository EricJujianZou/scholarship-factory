# Progress / learnings

## Codebase Patterns

- FastAPI + sqlite3 stores (OpportunityStore/ProfileStore): both open
  `sqlite3.connect` with default `check_same_thread=True` at construction.
  FastAPI runs sync `def` endpoints in a threadpool, so a store built once
  at app-construction time raises `ProgrammingError` cross-thread. Fix:
  construct stores per-request inside the endpoint body (cheap for a
  single-user local sqlite service), not at app/module scope.
- `RankedResults`/`RankedOpportunity` (rank.py) already pair parsed values
  (`deadline: date | None`, `reward: MoneyValue | None`) with the verbatim
  `Opportunity` strings, and pydantic serializes `None` to JSON `null` for
  free - no extra serialization model needed for "never invent missing
  facts" API contracts.
- To assert a literal string (e.g. "no deadline found") appears in a
  static HTML page, keep it as a literal in JS rather than building it
  via template interpolation (`` `no ${label} found` ``) - the interpolated
  form never appears verbatim in the source file.
- Any dashboard that renders scraped/remote content (titles, org names,
  URLs from JSON-LD extraction) via `innerHTML` must escape every
  interpolation (`escapeHtml()`) and scheme-validate URLs before using
  them as `href` (`safeUrl()` rejecting non-http(s), e.g. `javascript:`).
  TestClient/pytest run no JS, so this can only be verified by a source
  contract test (helper functions exist, raw `${opp.field}` interpolation
  absent) plus asserting the API returns the raw value unescaped in JSON
  (JSON isn't HTML - escaping is the renderer's job, not the API's).
- `refresh.py` (GH-44): a narrow `store.set_status(id, status)` (writes only
  the status column) is how you bump a status without also bumping
  `last_seen` - `store.update()` always bumps `last_seen`, which is correct
  for `refreshed`/`changed` but wrong for `unreachable` (we didn't see the
  record, so nothing about it should look freshly observed).

- Fixture-driven tests hid three live-only defects (first real run, 2026-07-31).
  `test_pipeline`/`test_traverse` hand-build `ExtractionResult`s with
  `apply_url` already set, so they never exercised what the LLM actually
  receives. Lesson: for any stage whose input is LLM output, at least one test
  must run the real `clean_html` -> prompt path, or a whole feature (link
  traversal) can be dead in production while the suite is green.
- `PoliteFetcher._fetch` forwards `timeout`/`user_agent`/`transport` kwargs, so
  a fake fetch injected for tests must accept `**kwargs`. Its robots.txt fetch
  goes through the same injected fn - a fake returning HTML parses as an empty
  ruleset (allow-all), which is usually what you want in a test.
- Free-tier Gemini returns a persistent 503 "high demand" on some models
  (3.5-flash) while others (3.6-flash) serve the same payload fine. Treat a 503
  as a model-availability signal, not only a transient one - google-genai has
  already retried internally by the time it surfaces.

## Close-out

- GH-44 closed out manually after the harness run was quota-interrupted at
  the test stage (`status: quotad`, not failed); the review/document stages
  never ran, so their observability logs are legitimately absent. Tests
  re-verified green (`uv run pytest -q`: 146 passed) before close-out.
- Review confirmed the two intentional design points read correctly in
  code: a re-check where a fact is no longer found yields status `changed`
  (the `new|refreshed|changed|unreachable` machine has no separate state;
  the outcome's `no_longer_found` records it), and `unreachable` is written
  via `store.set_status()` so `last_seen` is not bumped.
